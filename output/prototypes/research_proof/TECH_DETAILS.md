# Technical Details

## What It Does

Research Proof implements a six-stage pipeline for pressure-testing research claims, inspired by the scientific method's emphasis on falsifiability (Popper), pre-registration of criteria, and adversarial peer review. When used as a Claude Code skill, it instructs the model to systematically decompose compound claims into atomic propositions, generate falsifiable evidence plans, run adversarial checks for bias/fallacies/confounders, lock verification criteria before examining evidence ("frozen verifiers"), and produce a structured proof ledger with per-claim verdicts.

The standalone Python implementation (`research_proof.py`) mirrors this pipeline with concrete data structures and rendering logic, demonstrating the exact output format Claude is instructed to produce.

## Architecture

```
research_proof.py          — Full pipeline: extraction, evidence plans, adversarial
                             checks, frozen verifiers, proof ledger, verdict rendering
SKILL.md                   — Claude Code skill definition (structured prompt)
run.sh                     — Demo runner (mock data, no API keys)
proof_ledger.json          — Structured output artifact (generated by run.sh)
```

### Data Flow

```
Raw research text
  -> extract_claims()         — Split into atomic propositions
  -> build_evidence_plan()    — Per-claim confirming/falsifying evidence
  -> run_adversarial_checks() — Fallacies, confounders, biases, steel-man counters
  -> freeze_verifiers()       — Lock acceptance criteria pre-evidence
  -> evaluate_claim()         — Combine into ClaimResult with verdict
  -> render_full_report()     — Markdown report with proof ledger table
```

### Dependencies

- **Python 3.10+** (for `list[str]` type hints in dataclasses)
- **No external packages** — uses only `json`, `dataclasses`, `enum`, `textwrap`
- When used as a Claude skill: requires Claude Code with skills support

### Model Calls

The standalone demo makes **zero API calls** — it uses mock data to show the output format. When used as a Claude Code skill, the model itself fills each pipeline stage using its reasoning capabilities. No external API integration needed.

## Limitations

- **No live evidence retrieval.** The skill instructs Claude to reason about what evidence *would* confirm or falsify a claim, but does not fetch papers or data from PubMed, Semantic Scholar, etc. Pair with a search MCP for live lookups.
- **No statistical computation.** Frozen verifiers define thresholds (e.g., "p < 0.05 with Bonferroni correction") but Claude cannot compute statistics on raw data. This is a reasoning framework, not a stats engine.
- **Single-model adversarial.** The adversarial checks are performed by the same model making the claims. For stronger adversarial review, run claims through multiple models or human reviewers.
- **Verdict quality depends on model capability.** More capable models (Opus) produce better adversarial reasoning than smaller models.

## Why This Matters for Claude-Driven Products

| Use Case | Application |
|----------|-------------|
| **Lead-gen / Marketing** | Pressure-test competitor claims before building counter-narratives. Verify ROI stats cited in whitepapers before using them in sales decks. |
| **Agent Factories** | Embed as a verification step in multi-agent pipelines — any agent making a factual claim gets it routed through the proof pipeline before publishing. |
| **Ad Creatives** | Validate statistical claims ("50% faster", "3x more effective") before they go into ad copy, reducing regulatory risk. |
| **Voice AI** | Pre-verify claims that voice agents will state to customers, preventing confident delivery of unverified information. |
| **Research Teams** | Pre-register hypotheses and track evidence systematically, producing audit-ready proof ledgers for internal review. |
